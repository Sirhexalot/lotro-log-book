## Player texts in DE, EN and FR

- Write for LOTRO players: say what they can find, learn, equip or do next. Use familiar player language, no developer jargon or UI technical terms such as „Breadcrumbs“/„Brotkrumen“; describe the concrete benefit for players instead. Atmosphere belongs in accompanying texts; menu, filters and buttons stay unambiguous. „Spielstand importieren“ stays.
- Take official game names from the respective client. Community language helps with your own texts but does not replace game names. Original game texts stay unchanged. If a name is missing, do not translate freely.
- If a detail is missing, leave out the field and, where applicable, the heading. No lines with „nicht geprüft“, „nicht belegt“, „ungewiss“, „not recorded“ or „non attesté“ and no invented substitute values. Missing progress is not `0 %`, missing crafting knowledge is not „nicht gelernt“. A deliberately selectable filter value may name which entries it selects.
- Do not show blanket hedging or liability notes such as „keine Zusage“. Instead, name evidenced, concrete limitations directly at the matching entry or filter; if a detail is missing, leave out field and heading.
- Keep hints where players can use them: empty results, no route, repeat import, concrete usage help. No explanation of internal data sources or verification steps as standard text.
- Change and check DE (`du/dein`), EN and FR (`vous/votre`) together: visible texts, usage help, page titles and search engine descriptions. Also check empty results, filter changes and views with and without character progress.

## Data sources and limits

- Map images and texts come from our own client DAT export. Map tree, boundaries, regions and parent maps from the game definitions (`parchmentMaps.xml`, `maps/maps/maps.xml`, `maps/links.xml`), read via `../MagicQuestLog/tools/game_maps.py`. Which place a position stands in comes from the client's landblocks (`landblocks.xml`: area per block, dungeon per block and cell) plus `geoAreas.xml` and `dungeons.xml`, read by `tools/zonen.py`. The Companion repository checkout `~/Developer/Lotro/companion/lotro-data/lore/` is newer than its application folder, so the newer of the two landblock files is used. **No MoorMap geometry as a current web source.** MoorMap map numbers serve only the optional plugin button.
- `hole_karten.py` exports correctly localised images (default `--quelle dat`); `baue_webp.py` generates WebP. The same image file does not mean the same coordinate frame for map variants. Preserve IDs and frames of every variant.
- `build_daten.py` reads `../MagicQuestLog/plugin/MagicQuestLog/Data/Quests_<sprache>.lua` or `Deeds_<sprache>.lua`. Both come from the local plugin checkout; the iCloud copy is only a fallback when the local file is missing (among other things it contains no `theme:` paths, which is why the theme tiles and `th` were missing). For quests always include `QuestDetails_<sprache>_*.lua`: description, steps, objectives and rewards come from them. The web build merges them instead of reloading them on open like the plugin. **Deeds always come from the DAT export via the shared plugin generator** (`python3 tools/build_taten_daten.py`); `build_daten.py --art taten` reads the local plugin output for that, never the iCloud copy. Exact duplicates carry `replaced_by`; the website filters the old ID, maps progress onto the new one and redirects old deed addresses with 301.
- Important web fields: `i` stable ID, `g` giver name, `gt` giver location, `t` objectives, `s` steps, `rw` rewards, `v/vo/vl/vb` prerequisites, `rf` reputation source, `fk` map/navigation paths, `x` session game, `e` excluding alternatives. `h` are enemy locations, `hz` locations of quests belonging to a deed; do not output either as an exact deed objective position.
- Entries without an evidenced position stay searchable and in the catalogue but get no invented map point. A missing assignment is not the same as a missing image. Unusable map frames stay without points. By explicit decision on 23.11.2026, a named interior may use the client's own basemap image and a pin only when its landblock resolves to that room and the basemap frame contains the recorded point; interior coordinates never get world-map or travel actions.
- Do not take pins from LOTRO Wiki or LOTRO Completionist; no hand-drawn Garan/MoorMap detail images. Citing a source is not a rights clearance. Damien has allowed the library use; that is **not** a blanket clearance of the game content by its rights holders.
- Missing from the imported journal means neither „nie gespielt“ nor certainly „annehmbar“. Do not count session games and quests excluded by completed alternatives as feasible open quests; an evidenced completion takes precedence. Catalogue numbers are no proof of independently playable quests.
- Measured against the local web data on 08.11.2026 per language: **15.118 quests, 5.528 deeds, 6.564 reward items, 7.924 recipes, 10 professions, 220 areas and 6 regions**; on 10.11.2026 additionally **114 factions and 2.809 landmarks**. Derive numbers for changes from the actually built data, do not take them from old plugin/export states.
